# 高帧率与吞吐预算

固件 0.4.0 解除固定 15fps 配置。`/etc/mohism/performance.conf` 是启动时的统一配置来源，USB 描述符、应用参数和 FSIN PWM 从同一配置生成；修改后须停止 VINS、重启 USB gadget，再启动 VINS，主机需要重连。

```sh
CAPTURE_FPS=120
USB_FPS=60
DEPTH_FPS=30
```

这些参数设置请求频率。采集支持 15/30/60/120，USB 支持 15/30/60，稠密深度支持 15/30/60/120 且不超过采集率。高速度优先的开发配置请求双目原生 1280×800@120、320×200 的稀疏视觉跟踪逐处理帧运行、稠密深度请求 30Hz、双目 USB 输出请求 60Hz、深度 USB 请求 30Hz。可把 DEPTH_FPS 设为 60 或 120 评估计算成本，结合运行统计选择配置。

## 采集与处理

SDK OV9281 驱动有两个同为 1280×800 的模式表，标称 30 和 120fps；原先按分辨率选模会先命中 30fps。板级 `mohism,high-speed-readout` 选择已有 120fps 寄存器表。实际外触发速率由 PWM 决定，读出模式、曝光和触发接受条件共同决定输出频率，使用相机序号统计采集率。

采集先丢弃已排队的旧缓冲，再转换最新 RAW10，避免逐张转换积压帧。队列有界，处理跟不上会跳帧而非无限增加延迟。稀疏双目跟踪/PnP 不依赖整幅 SGBM；稠密深度按时间独立限频，未计算时当前处理帧的深度为零。双目与深度现在分别枚举为独立 UVC 功能，深度流只更新实际计算结果，可重复最近深度；超过 200ms 没有发布结果则清零。两路都没有共享帧号或曝光元数据，不能据 UVC 帧数推断独立有效图像数。

MAVLink 移除原来的 20Hz 限速，每个新的有效估计时间戳最多发一次。USB/串口背压时合并尚未开始发送的旧里程计，保留最新估计；已写出部分的包会先完成，避免损坏协议。输出频率随实际估计更新，每条消息对应一个新估计。

ARM 视觉库保留 NEON 并使用 `-O3`，应用 Release 构建同样使用 `-O3`。关闭 Buildroot 默认给 OpenCV 启用的 fast-math，并显式保留估计器的 NaN/Inf 检查语义。

## USB 预算

双目为 640×200 YUYV，每帧 256000 字节；深度为 320×200 Z16，每帧 128000 字节。HS 双目等时端点每 125µs 最多 2048 字节，深度端点最多 1024 字节，合计负载预算上限 24.576MB/s，还须扣除 UVC 头等开销。深度 USB 频率取 `min(USB_FPS, DEPTH_FPS)`。

|双目 / 深度请求帧率|纯帧数据 MB/s|说明|
|---|---|---|
|15 / 15|5.76|低带宽配置|
|30 / 30|11.52|低带宽配置|
|60 / 30|19.20|默认开发配置|
|60 / 60|23.04|接近端点负载预算|

端点按描述符最大包预留总线时间，降低深度帧率不会等比例降低预留量。并发测试同时打开双目、深度和两个 ACM。

原生双目 1280×800 灰度即使不带深度，60fps 也要 122.88MB/s；不能通过修改帧率参数使当前 USB2 链路传出这些未压缩图像。原生双目 RAW10 解包为 16 位时，120fps 的摄像头缓冲写入量约 491.52MB/s，尚未计 CPU 读取、缩放及处理。是否达到预期取决于 MIPI、DDR、CIF、CPU 与温度下的实测。

## 运行测量

每 5 秒原子更新 `/run/mohism-status.json`，从 USB 调试 Shell 读取：

```sh
cat /run/mohism-status.json
```

统计文件包含请求率、相机序号进展率、处理帧率、有效 VIO 率、实际稠密深度更新率、左右跳帧数、相机序号重启、处理耗时 P50/P95、图像内核时间戳到处理结束的年龄 P95、双目及深度各自的 UVC 完成缓冲数、重复缓冲数和 streaming 状态。帧率自进程启动累计，耗时统计保留最近 512 项。曝光时序由波形测量，帧年龄包含 CIF 时间戳偏移。主机接收和保存数量由主机工具单独统计。

性能测试同时记录逻辑分析仪的触发/曝光波形、主机 UVC 接收及重复帧、MAVLink 消息时间戳、CPU/RSS/温度与统计文件。调整配置时比较同一负载下的统计。`scripts/verify-performance.py` 和 profile 回归检查配置及软件时间路径的一致性。
