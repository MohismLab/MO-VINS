# 高帧率与吞吐预算

固件 0.3.0 解除固定 15fps 配置。`/etc/mohism/performance.conf` 是启动时的统一配置来源，USB 描述符、应用参数和 FSIN PWM 从同一配置生成；修改后须停止 VINS、重启 USB gadget，再启动 VINS，主机需要重连。

```sh
CAPTURE_FPS=120
USB_FPS=60
DEPTH_FPS=30
```

这些是请求值，尚未由实板验证。采集支持 15/30/60/120，USB 支持 15/30/60，稠密深度支持 15/30/60/120 且不超过采集率。高速度优先的开发配置请求双目原生 1280×800@120、320×200 的稀疏视觉跟踪逐处理帧运行、稠密深度请求 30Hz、USB 输出请求 60Hz。可把 DEPTH_FPS 设为 60 或 120 评估计算成本；不能保证该单核 SoC 同时完成所有请求。

## 已改的限制

SDK OV9281 驱动有两个同为 1280×800 的模式表，标称 30 和 120fps；原先按分辨率选模会先命中 30fps。板级 `mohism,high-speed-readout` 选择已有 120fps 寄存器表，不通过修改模式标签伪造提速。实际外触发速率由 PWM 决定，读出模式、曝光、触发接受条件和双路 CIF 均需实测。`VIDIOC_S_PARM` 的请求不能替代传感器选模和真实帧计数。

采集先丢弃已排队的旧缓冲，再转换最新 RAW10，避免逐张转换积压帧。队列有界，处理跟不上会跳帧而非无限增加延迟。稀疏双目跟踪/PnP 不依赖整幅 SGBM；稠密深度按时间独立限频，未计算时整幅深度为零，绝不把旧深度与新左右图混用。这样主机不一定每个 USB 帧都有有效深度。当前 USB 打包没有帧号或曝光元数据，不能据 UVC 帧数推断独立有效图像数，这是产品交付前必须补齐的协议项。

MAVLink 移除原来的 20Hz 限速，每个新的有效估计时间戳最多发一次。USB/串口背压时合并尚未开始发送的旧里程计，保留最新估计；已写出部分的包会先完成，避免损坏协议。输出频率随实际估计更新，不复制旧位姿制造更高频率。

ARM 视觉库保留 NEON 并使用 `-O3`，应用 Release 构建同样使用 `-O3`。关闭 Buildroot 默认给 OpenCV 启用的 fast-math，并显式保留估计器的 NaN/Inf 检查语义；不以破坏数值异常检查换取性能。优化标志不等于实测加速比例。

## USB 预算

打包仍为 960×200 YUYV，每帧 384000 字节；左右各 320×200 灰度，第三块为 320×200 的 uint16 毫米深度。配置的 HS 等时视频端点每 125µs 最多 3072 字节，预算上限为 24.576MB/s，还必须扣除视频负载头等开销。

|UVC 请求帧率|纯帧数据 MB/s|当前端点预算|
|---|---|---|
|15|5.76|留有较多余量|
|30|11.52|须并发验证|
|60|23.04|接近预算，须测完整率和双 ACM 并发|
|120|46.08|不支持当前打包与端点配置|

原生双目 1280×800 灰度即使不带深度，60fps 也要 122.88MB/s；不能通过修改帧率参数使当前 USB2 链路传出这些未压缩图像。原生双目 RAW10 解包为 16 位时，120fps 的摄像头缓冲写入量约 491.52MB/s，尚未计 CPU 读取、缩放及处理。是否达到预期取决于 MIPI、DDR、CIF、CPU 与温度下的实测。

## 运行测量

每 5 秒原子更新 `/run/mohism-status.json`，从 USB 调试 Shell 读取：

```sh
cat /run/mohism-status.json
```

文件区分请求率、相机序号进展率、处理帧率、有效 VIO 率、实际稠密深度更新率、左右跳帧数、相机序号重启、处理耗时 P50/P95、图像内核时间戳到处理结束的年龄 P95、UVC 完成缓冲数与重复缓冲数。帧率自进程启动累计，耗时统计保留最近 512 项。相机序号进展不能证明曝光正确，帧年龄包含尚未标定的 CIF 时间戳偏移，UVC 缓冲完成也不证明主机已成功接收/保存。

上板同时记录逻辑分析仪的触发/曝光波形、主机 UVC 接收及重复帧、MAVLink 消息时间戳、CPU/RSS/温度与统计文件。调整性能配置后必须用这些数据比较；不能把 x86 回放速度当作 RV1106 性能。`scripts/verify-performance.py` 和 profile 回归只证明配置及软件时间路径一致。
