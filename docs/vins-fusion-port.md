# 视觉惯性算法 0.5.0

本版将运行时后端从松耦合滤波改为双目与 IMU 联合优化。完整上游源码固定在 `be55a937a57436548ddfb1bd324bc1e9a9e828e0`；来源及移植组件见 `sources.lock.json`，修改与许可证见 `third_party/VINS-Fusion/NOTICE.md`。这是一套适配本项目的实现，未照搬上游 ROS 应用、DBoW 词典或发布系统。

## 求解过程

前端保持特征 ID，使用时域与左右双向 LK、空间补点、校正后的双目几何检查。运行时输出归一化左右观测和速度，直接进入滑窗；不再把独立 PnP 位姿当作滤波观测。PnP 只用于运动初始化、回环验证，以及单独的视觉回归测试。

滑窗状态包括每帧位姿、速度、加计/陀螺偏置及特征逆深度。直接移植的三个投影因子与 IMUFactor 在同一个 Ceres 问题中求解，使用视觉 Cauchy 损失、单线程 DENSE_SCHUR。退出窗口的旧位姿、速度/偏置和相应逆深度通过 Schur 补形成平方根先验；仍在窗口中的观测不会重复计入先验。参数存储地址稳定，先验在下一次边缘化完成后才释放旧状态。

预积分使用中点法、偏置雅可比和协方差。连续噪声密度按实际 dt 离散化，白化使用带微小正则项的 LLT 求解。每个图像时刻均使用 IMU 插值后的精确端点。处理频率高于 `optimizer_fps` 时，帧间输出惯性传播，后续联合求解消费累积区间。

初始化有两条路径：连续静止样本检查，或度量双目运动与 IMU 对齐。运动初始化求解陀螺偏置、速度、重力与加计偏置，检查运动激励、残差和重力幅值。旧 `Filter` 仍用于静止初始化及原有隔离测试，不再承担运行时视觉融合。

代码拒绝非有限值、时间倒退、过大间隔、超出当前 IMU 支持范围的数据和优化失败。视觉求解后检查正深度与左右重投影一致性，要求至少 12 个可用特征和 50% 一致性。状态、特征、采样缓冲、关键帧和地图文件均有上限。门限不能覆盖所有错配场景，错误标定仍会造成系统误差。

## 回环、地图与输出坐标

回环使用 ORB 描述子匹配、互检、PnP RANSAC 与 LM、空间覆盖率、倾斜一致性及当前双目深度验证，并要求两次相容候选。没有使用上游 BRIEF/DBoW 词典。四自由度图优化位置与航向，保留重力确定的横滚和俯仰。关键帧被淘汰时，相关图约束边缘化进入先验。

图修正只作用于对外位姿，局部 VIO 和滑窗先验保持连续。输出位置改变超过 5cm 或旋转超过 0.02rad 时增加 `ODOMETRY.reset_counter`；跟踪重置也增加该计数。计数为进程内模 256，进程重启从零开始，接收端还必须检查时间戳。

地图默认写入 `/userdata/mohism-map.yml`。文件包含标定指纹、关键帧、描述子、度量点、边与边缘化先验，采用临时文件、fsync 和原子替换。载入最多 32MB，先完整验证再替换当前地图；不兼容或损坏地图被拒绝并记录日志。重启后需完成当前 VIO 初始化，再通过几何验证重定位；无法匹配时继续输出当前局部坐标，不保证跨会话连续。

关键帧最多 5Hz，默认保留 200 帧；持续达到上限时只保留约 40 秒的视觉检索历史。图先验可以保留已淘汰的约束，但不能让已经删除的图像重新参与地点检索。长期建图需要另行制定保留策略和测量资源。当前镜像的 userdata 分区为 16MB，原子保存需要同时容纳旧地图和新临时文件；200 帧及复杂图先验可能超出可用空间。部署前应测量地图大小，减少保留帧数或调整存储布局。写盘失败只记录错误，VIO 继续运行，不能据此假定地图已保存。

## 配置与升级

板端 `/userdata/calibration.yml` 覆盖默认标定；未经实测的模板仍为 `calibrated: 0`，只提供预览和控制服务。

| YAML 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `window_size` | 6 | 滑窗帧数 |
| `max_features` | 100 | 滑窗特征上限 |
| `optimizer_fps` | 30 | 联合求解请求频率 |
| `solver_iterations` | 8 | 每次求解最大迭代次数 |
| `solver_time` | 0.04 | Ceres 求解时间预算，秒 |
| `pixel_noise` | 0.7 | 投影标准差，处理图像像素 |
| `estimate_extrinsics` | 0 | 在线相机/机体外参 |
| `estimate_time_offset` | 0 | 在线时间偏移 |
| `loop_closure` | 1 | 回环与地图 |
| `loop_max_keyframes` | 200 | 有界检索库，允许 30–1000 |
| `map_file` | `/userdata/mohism-map.yml` | 持久化路径，空字符串关闭保存 |

时间预算是求解器的停止请求，单次迭代、前端、边缘化和图优化仍可能超时，不构成实时截止保证。不能从 PREEMPT_RT 推导出算法能实时运行。

在线标定默认关闭。它要求完整滑窗、累计转动大于 0.5rad 且三轴角速度激励矩阵最小特征值大于 0.002。双目相对外参使用强约束，时间偏移限制在 ±20ms。时间修正对新 IMU 端点和一阶特征速度生效，历史预积分区间不会随时间偏移重建。合成测试覆盖了已标定状态下的估计稳定性，尚未证明不同误差初值和真实传感器上的收敛范围，不能替代离线标定。

MAVLink 保持 8 个参数，版本为 500。`ACC_NOISE`、`GYRO_NOISE` 为连续密度，新增 `ACC_BIAS_RW`、`GYRO_BIAS_RW` 表示偏置随机游走。旧 `POSE_POS_SD`、`POSE_ROT_SD` 被忽略，升级后需重新核对噪声配置。详见 [协议](protocol.md)。

`/run/mohism-status.json` 增加窗口/特征数、联合求解及边缘化次数、最近求解时间和代价、回环/重定位次数、时间偏移与标定激活状态。处理/输出统计继续保留。

## 软件验证

```sh
sh scripts/build.sh host
sh scripts/build.sh sanitize
sh scripts/build.sh arm-check
sh scripts/build.sh refresh-rootfs
sh scripts/build.sh package
```

主机共 11 项 CTest，加上 MAVLink 伪串口、图像保真及双 UVC 描述符测试。新增的核心检查包括：

- 三种投影因子的非零旋转、不同左右速度和时间偏移下数值雅可比；IMU 因子数值雅可比。
- 消元后先验与原标量系统的 Schur 信息等价；45 帧度量运动包含 41 次边缘化。
- 少量严重视觉错配的联合估计恢复；双在线标定开关在多轴运动下激活，已标定输入的位姿/外参/时间估计保持稳定。
- 运动初始化的重力、陀螺偏置和速度，以及不可观运动拒绝。
- 有界回环库、错误双目几何拒绝、漂移修正、地图保存载入、损坏地图拒绝及跨会话重定位。
- 评估工具不拟合尺度，正确处理相机杆臂、相对误差和重置分段。

ASan/UBSan 使用非 PIE 主机程序；ARM 数值、初始化和地图测试通过 QEMU 执行。它们检查代码路径和目标 ABI，不代表实板速度、功耗或实时性。旧视觉轨迹测试仍验证独立 VO，不应作为紧耦合精度证据。

## EuRoC MH_01_easy

2026-10-28 完整回放 3,682 对图像及 36,820 条 IMU 数据。相机原图 752×480，处理 320×200，窗口 6、100 特征、8 次迭代、40ms 求解预算、20Hz 优化、回环开启。数据、真值与原标定的固定来源和 SHA256 见 `qualification/euroc-mh01-sources.json`，标定文件为 `host/calibration/euroc.yml`，不得用于实际板卡。

官方分发站在此次环境中下载超时，bag 来自镜像，其 SHA256 与镜像 LFS 对象一致。真值使用上游 ORB-SLAM3 保存的原始 IMU 位姿，经原始标定转换为左相机位姿；不使用 bag 中 Leica 点位替代机体真值。另一个派生左相机参考文件的姿态列未通过标定变换一致性检查，因此没有用于最终评估。

| 指标 | 本次结果 |
| --- | --- |
| 有效输出 | 3,619 / 3,682，98.29% |
| 成功匹配真值 | 3,607 帧 |
| 重置或地图修正计数变化 | 25 次 |
| 分段位置 ATE RMSE / p95 | 0.05988m / 0.15406m |
| 1 秒相对平移 RPE RMSE | 0.05476m |
| 1 秒相对旋转 RPE RMSE | 0.63353° |
| 主机平均单帧处理时间 | 56.23ms |

ATE 对每个连续有效且计数相同的段单独执行 SE(3) 对齐，**没有拟合尺度**。全程单一对齐 ATE 留空，分段 RMSE 不表示连续全程误差。63 帧无效；状态包括等待初始化、预热、21 帧双目观测不足、20 帧 IMU 输入超出当前支持范围。25 次计数变化包含跟踪重置与地图坐标修正，不能直接当作 25 次跟踪丢失。参考与输出时间覆盖不同，不能将未匹配帧隐去后声称全覆盖。完整报告保留逐段时长、误差和状态计数，见 `qualification/euroc-mh01-results.json`。

单次单序列的结果未覆盖弱纹理、动态物体、振动、滚动快门及长期运行。主机耗时不代表板端性能；当前结果也没有证明目标板能维持 20Hz 联合优化。回放在离线模式下不丢帧，实机有界队列的丢帧行为还需测量。

复现时先安装可选 `rosbags==0.11.9`，提取 bag：

```sh
python3 host/euroc_bag.py out/MH_01_easy.bag out/datasets/MH_01_easy
cmake -S . -B out/benchmark -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build out/benchmark --target mohism-replay -j4
out/benchmark/mohism-replay host/calibration/euroc.yml out/datasets/MH_01_easy out/MH01-trajectory.csv
python3 host/evaluate_trajectory.py out/MH01-trajectory.csv out/MH-imu-groundtruth.txt host/calibration/euroc.yml out/MH01-evaluation.json --reference-frame imu
```

编译和回放应在 `mohism-build:bookworm` 容器中运行，方法与 README 的构建说明一致。结果受求解时间预算和主机速度影响，不要求每次逐位一致。
