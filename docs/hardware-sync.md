# 相机与 IMU 共同硬件同步改版

状态：**方案已提出，未应用到 EDA，未实现为已验收固件功能。** 用户于 2026-10-28 确认尚未生产，可在投板前修改。Bridge 检查返回无客户端，因此不能修改原理图或宣称 DRC 已通过。现有证据仍是 `hardware/netlist.json`；后续连接必须重新导出核对。

## 当前连线与必须处理的问题

现有 U3 INT1（4 脚）接 U1 GPIO1_B0（77 脚），中断已接；INT2（9 脚）没有网络。左右相机 B5 FSIN 共接 U1 GPIO3_D3（9 脚）。U1 GPIO3_VCC（43 脚）和 U3 VDDIO（5 脚）接 3.3V，相机 IO 电源为 1.8V。故现有直接 FSIN 连线的电平兼容性也需要在投板前解决，不能仅向该网再接 IMU。

ST 数据手册 DS12140 Rev 2 的 Table 2 / Table 24 表明 INT2 可用作 DEN，且复位默认输出低；Table 59 定义 DEN 触发模式，Table 67 描述把 DEN 信息写入传感器数据最低位。官方寄存器驱动也提供 DEN 配置接口。DEN 是数据标记/选通功能，不能由此推导 IMU ADC 与相机曝光严格同相或滤波延迟为零。

## 建议连线

|网络|端点与作用|
|---|---|
|SYNC_PWM_3V3|U1.9 GPIO3_D3/PWM1_M2，硬件脉冲源|
|SYNC_REF_3V3|门控后的共同事件，接 U3.9 INT2/DEN 与 U1.78 GPIO1_B1 反馈输入|
|CAM_FSIN_1V8|共同事件经过固定方向电平转换，接 U4.B5、U12.B5|
|SYNC_ENABLE|U1.73 GPIO1_A1 控制门控；外部下拉使上电默认关闭|
|IMU_INT|保持 U3.4 → U1.77，独立报告 IMU 数据就绪|

U1.78 和 U1.73 在当前网表为空闲，仍需 PCB/复用/启动上下文核查；这里只是分配建议。门控输出在 IMU 配置完成前必须保持禁用，避免对复位时输出低的 INT2 强推高电平。电平转换器应按上电顺序、掉电容忍、输出使能和脉冲时序选型，不能以自动方向 I²C 转换电路代替未经验证的推挽时钟缓冲。新增器件尚未选定和放置。

共同事件从 PWM 经门控后同时到达 IMU DEN、SoC 反馈和相机电平转换路径。相机间共享同一 FSIN 支路；测试点必须覆盖门控前后和相机端。既有 SCCB、PWDN 等跨 IO 电源域信号也须一并核对。

## 固件必须完成的闭环

1. 驱动上电先禁止门控，复位并配置 IMU DEN 输入、极性、标记轴和采样/FIFO；确认没有在 INT2 路由输出中断，再开放共同脉冲。关机、解绑、超时和恢复先关门控。
2. 从 FIFO 获取加速度、角速度及芯片时间戳；识别并剥离占用数据最低位的 DEN 标志，另行输出事件序号。驱动异常、FIFO 溢出与事件丢失必须上报，不能静默继续。
3. 反馈通路关联触发计数、左右帧序号、DEN 标志与同一时间基准。内核 GPIO IRQ 的到达时间仍有延迟；不能称为硬件捕获时间戳。RV1106 数据手册说明 PWM 有 capture 功能，但当前 SDK PWM 驱动没有相应 capture 实现，不能把该能力当作已可用。
4. 标定 FSIN 到左右实际曝光中心、DEN 标记对应采样及 IMU 滤波群延迟。ADC 自由运行与共同事件标记的差别必须反映在误差预算；若验收要求严格锁相，需重新评估 IMU/硬件架构，不能靠 DEN 接线承诺。
5. 算法要求可验证的事件匹配；断线、错序、复位、温漂或长时间漂移越界时撤销有效 VIO 输出。当前软件时延参数仅用于开发，不能充当共同同步验收结果。

上述新路径尚未在驱动中启用，当前固件仍采用 INT1 IRQ 时间戳与软件时延标定。投板门禁脚本 `scripts/check-hardware-sync.py` 会对现有网表失败，直到新连线导出并核对；它只核对网络，不替代器件、波形、时间误差和 PCB 验收。
